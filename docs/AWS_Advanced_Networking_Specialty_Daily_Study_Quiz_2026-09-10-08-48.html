Subnet CIDR reservations for deterministic EC2 prefix delegation: prefix versus explicit pools, availability accounting, and lifecycle behavior

Primary feature lesson sourceSubnet CIDR reservations - Amazon Virtual Private Cloudhttps://docs.aws.amazon.com/vpc/latest/userguide/subnet-cidr-reservation.html

Classification/platform: Official AWS feature and configuration documentation. Source date: no update date displayed; checked 2026-09-10. Supports: Reservation types, overlap rules, automatic prefix selection, deletion behavior, and available-address accounting.

Scenario support sourcePrefix delegation for Amazon EC2 network interfaces - Amazon Elastic Compute Cloudhttps://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-prefix-eni.html

Classification/platform: Official AWS implementation and workload-integration documentation. Source date: no update date displayed; checked 2026-09-10. Supports: Automatic and manual prefix delegation, fixed prefix sizes, ENI quotas, Nitro requirements, operating-system configuration, and source/destination checks.

Essence / mental model

A subnet CIDR reservation is allocation policy inside a subnet, not a route and not an address already attached to a workload. A prefix reservation sets aside a contiguous IPv4 or IPv6 range for prefix delegation to network interfaces; an explicit reservation protects individual addresses that operators will assign manually. The distinction changes capacity reporting. Creating a prefix reservation reduces the subnet’s available-address count immediately, while an explicit reservation reduces the count only as reserved addresses are assigned. AWS may allow a new reservation to cover addresses already in use, but creating it does not move or unassign those addresses. Deleting the reservation releases only unused capacity; addresses already attached remain attached. This makes reservation state a planning boundary rather than a destructive ownership transfer.

Architecture, dependencies, and normal flow

Use prefix reservations when a container platform, virtual network appliance, or other dense workload needs predictable contiguous blocks. EC2 prefix delegation selects from a prefix-type reservation when one exists; otherwise it selects from the subnet’s unreserved CIDR. Automatic allocation across multiple reservations is not an affinity mechanism—AWS can choose a qualifying range—so do not encode Availability Zone, tenant, or security meaning in “the first reservation.” Manual prefix assignment checks for overlap and must fit the fixed EC2 sizes: IPv4 /28 or IPv6 /80. A delegated prefix counts as one address against the ENI’s address quota even though it exposes a block to the instance. Confirm the instance is Nitro-based and that the guest OS or CNI configures addresses and routes from the delegated block.

Essence / mental model

Accelerated Site-to-Site VPN changes the internet-facing segment of a VPN path. The customer gateway sends encrypted traffic to the closest AWS edge and Global Accelerator carries it across the AWS global network toward the Transit Gateway attachment. AWS creates two managed accelerators, one per tunnel; they are implementation resources that customers cannot view or administer through the Global Accelerator console or API. Acceleration is available only for VPN connections attached to a Transit Gateway, not a virtual private gateway, and it cannot share an AWS Direct Connect public virtual interface. The two tunnels still remain independent availability paths. Acceleration improves path consistency; it does not change BGP correctness, cryptographic negotiation, routing domains, or application authorization.

Architecture, dependencies, and normal flow

Treat acceleration as a creation-time property. AWS does not let you toggle it on an existing VPN connection, so migration means building a new connection, configuring both new tunnel peers on the customer gateway, shifting routes with a defined preference, validating traffic, and then deleting the old connection. NAT traversal is required. The customer gateway must initiate IKE for accelerated tunnels even though standard Site-to-Site VPN offers AWS startup and restart options under specific conditions. If certificate authentication creates larger IKE messages, the customer device must support IKE fragmentation because Global Accelerator has limited fragmentation support. Map these constraints to device capabilities before ordering the change; latency measurements alone are not sufficient design evidence.

Primary feature lesson sourceTransit gateway policy tables in AWS Transit Gateway - Amazon VPChttps://docs.aws.amazon.com/vpc/latest/tgw/tgw-policy-tables.html

Scenario support sourceExample: Steering traffic to a security appliance in AWS Transit Gateway - Amazon VPChttps://docs.aws.amazon.com/vpc/latest/tgw/tgw-policy-tables-example.html

Classification/platform: Official AWS worked architecture and CLI example. Source date: no update date displayed; checked 2026-09-10. Supports: Sensitive-source steering to a firewall route table, catch-all behavior, return lookup, and policy-table creation and association commands.

Essence / mental model

Transit Gateway policy-based routing (PBR) separates traffic classification from destination-route lookup. An ordered policy table evaluates source and destination CIDRs, source and destination ports, and protocol, then selects a Transit Gateway route table. That chosen route table performs the normal destination lookup and identifies the next attachment. Because the policy table replaces the standard route-table association on the source attachment, one attachment can be associated with a policy table or a Transit Gateway route table, but not both. This is not an inline firewall by itself; it is a deterministic way to choose which routing domain should forward a matching flow. A lower-numbered matching rule must be designed with the same care as an ACL priority.

Architecture, dependencies, and normal flow

Use a narrow rule for the traffic requiring different treatment and an explicit catch-all rule for all remaining traffic. In the AWS example, rule 100 matches source 10.1.10.0/24 and selects a firewall route table; rule 200 selects the default route table for everything else. The firewall route table must still contain a destination route toward the inspection VPC. When the firewall sends the packet back to the Transit Gateway, the gateway uses destination lookup on the route table associated with the firewall attachment; the source policy is not automatically replayed as symmetric service chaining. Therefore map both directions, ensure the appliance preserves the flow, and avoid a return route that bypasses or loops back into inspection.

Essence / mental model

Route 53 Profiles package DNS configuration for consistent association with many VPCs and accounts. A Profile can carry private hosted zones, Resolver forwarding or system rules, DNS Firewall rule groups, interface VPC endpoints, and Resolver query logging configurations. It can also set reverse DNS behavior, DNS Firewall failure mode, and DNSSEC validation. A VPC can have one associated Profile in a Region, and enabled Profile settings take effect immediately. The mental model is inherited DNS intent: the Profile owner curates common resources; a VPC association applies them without copying independent rule objects into every account. Local VPC DNS configuration can coexist and becomes part of a defined priority algorithm rather than an accidental override.

Architecture, dependencies, and normal flow

For an exact domain conflict, directly associated VPC configuration wins over the Profile. Across different suffix lengths, the most specific matching name wins. That means a Profile rule for test.example.com can beat a local rule for example.com, while an exact local example.com rule beats an exact Profile example.com rule. Document this matrix before migration. Share the Profile with AWS RAM in the same Region, choose read-only or admin/custom permissions, and remember that consumers cannot reshare a Profile. The default RAM permission lets consumers associate the Profile with VPCs but does not include AssociateResourceToProfile; if consumers must contribute resource associations, the owner needs a custom managed permission containing that action.

Essence / mental model
