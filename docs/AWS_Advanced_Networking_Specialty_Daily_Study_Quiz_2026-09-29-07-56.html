The IPAM pool, its locale, allocation rules, account or organization scope, and Elastic IP association are separate lifecycle objects that must be audited together. Security, governance, scale, and failure boundaries

Apply least privilege at identity, resource, endpoint, network, and application layers. ECS blue/green deployment with Service Connect runs a replacement task set alongside the original and uses test and production traffic paths to validate and shift service traffic deliberately. Lifecycle hooks, test traffic, deployment alarms, bake time, and rollback create separate gates; operators must correlate ECS deployment state, Service Connect proxy logs, target health, and application metrics. Log changes to shared controls and protect evidence from alteration by the service owner being investigated. Use purpose-built automation roles and review wildcard principals, broad CIDRs, and fail-open defaults. Availability is part of security: an over-broad deny, stale association, unreachable callback, or missing return path can create an outage without improving confidentiality. Use staged enforcement, expiring exceptions, and negative tests. At scale, codify configuration, validate it before deployment, observe it afterward, and reconcile drift only after confirming business ownership and intended path.

For high availability, use the feature’s documented multi-AZ/Region or multi-path capabilities where applicable, maintain an intentional rollback, and record account ownership.
