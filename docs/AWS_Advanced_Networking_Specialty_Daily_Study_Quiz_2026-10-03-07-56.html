Essence / mental model

An IPAM policy evaluates public IPv4 allocation requests against declared criteria and selects a destination pool, turning address sourcing into a governed control-plane decision instead of a ticket-driven manual choice. Policy priority is part of correctness: overlapping criteria can match the same request, so teams must design deterministic precedence and test both the intended winner and nonmatching cases. CreateIpamPolicy supports client-token idempotency; automation should persist the token and desired policy identity so retries do not create divergent policy objects after timeouts. Allocation compliance still requires observing the resulting resource, pool, account, Region, tags, and exception owner because successful policy creation is not proof that every later allocation matched the intended branch.   • A REST API private integration sends requests through a VPC link to an ALB or NLB listener, or to Cloud Map-discovered resources, without exposing the backend publicly.
  • For the newer VPC link model, the integration URI identifies the load balancer listener or Cloud Map service; using a load balancer DNS name where an ARN is expected produces a control-plane or routing failure.
  • API Gateway includes the stage name in the backend request path by default, so parameter mapping may be required when the private service expects a stage-neutral route.
  • TLS configuration can set the server name used for certificate validation, and end-to-end verification must separate API Gateway method deployment, VPC link status, listener rules, target health, DNS discovery, security groups, and backend logs.
